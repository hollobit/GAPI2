5. 시사점

  • 수요는 증명 끝났습니다. 커뮤니티가 4개월 만에 MCP 79종을 만들었다는 것은, 공식 Agent Access Layer(이용 절차 §6)가 나오면 즉시 소비할 개발자 생태계가 이미 존재한다는 뜻입니다. 반대로 지금은 품질·보안·키 관리가 제각각인 비공식 래퍼에 수요가 흡수되고 있습니다.
  • 파편화는 양방향으로 움직이기 시작했습니다. 신규 포털 22개가 더 발견되는 동시에, LOCALDATA처럼 data.go.kr로 통합·폐지되는 첫 사례도 나왔습니다. 통합이 예외가 아니라 정책이 되려면 국가데이터처의 거버넌스가 관건입니다.
  • 공식 1호(서울)의 형태가 시사적입니다. 자체 인프라가 아닌 민간 플랫폼(카카오 PlayMCP) 호스팅 + 선착순 100명 파일럿 — 빠른 실험으로는 훌륭하지만, 전국 단위 인프라의 대체재는 아닙니다. 중앙정부의 "검증 먼저" 기조와 결합하면, 운영형 공식 MCP의 공백은 당분간 커뮤니티가 메꾸게 됩니다.

방법론 · 한계

  • 포털 — 2025-05~2026-08 보도·공고 검색으로 후보 도출 후 전 후보를 직접 호출(HTTP 검증, 실패 시 DNS 이중 확인). 22개 신규는 전부 HTTP 200 실측. OpenAPI 여부는 발급 페이지를 직접 본 곳만 true로 처리한 보수적 값입니다.
  • MCP·도구 — 전 저장소를 GitHub API로 존재·스타·최근 커밋 검증(2026-08-04 기준 라이브 값). 서울 MCP·정부 발표는 1차 보도·공식 페이지로 확인. 기준선에 있던 dartpoint-mcp는 현재 어느 플랫폼에서도 확인되지 않아 제외했습니다.
  • 스타 수·활동성은 조사 시점 스냅샷이며, 저장소 수는 "존재 검증된 것"의 하한입니다(비공개·비GitHub 제외).
